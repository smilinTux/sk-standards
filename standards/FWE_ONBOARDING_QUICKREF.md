# FWE Onboarding Quick Reference

**Status:** One page for an agent (Claude, Codex, Jarvis, Pi) starting FWE work cold.
Read this, then [`FWE_AGENT_OPERATING_STANDARD`](./FWE_AGENT_OPERATING_STANDARD.md)
(rules), then [`FWE_MATTER_DOCUMENT_GENERATION_STANDARD`](./FWE_MATTER_DOCUMENT_GENERATION_STANDARD.md)
(architecture). Nothing here is a credential; names of secrets only.

**Why:** the 2026-10-17 drift happened because an agent did not know Windmill existed.
The first thing to learn is that it does, and where.

---

## 1. Five facts to hold

1. Documents are generated by the **worker** behind **Windmill** flows. There is no
   other path.
2. Matter files live in the Nextcloud Team Folder **Matters**, written only by the worker.
3. You change things by **PR** (reviewed by another lane), never by direct write, merge
   or deploy.
4. Missing input or missing source is a **HOLD**, never a guess.
5. The system is AI-first: an independent reviewer agent (different model and identity
   than the composer) satisfies approval. Human approval in Windmill (Casey or Chef,
   SSO) is an optional per-matter mode, `review_mode: "human"`. Mailing is a physical act.

## 4. Commands

```bash
# build the test context (needs the private fonts and border image) and run the worker tests
FWE_FONT_DIR=<private-font-dir> python3 scripts/fwe/build-worker-context.py /tmp/fwe-ctx
cp deploy/fwe/worker/test_*.py /tmp/fwe-ctx/ && cd /tmp/fwe-ctx
FWE_WINDMILL_DIR=<repo>/deploy/fwe/windmill python -m pytest -q

# corpus isolation and registry tests
python -m pytest scripts/test_fwe_isolation.py scripts/test_corpus_packs.py scripts/test_pack_index.py scripts/test_fwe_registry.py

# what is running on NAM (from the manager)
docker service ls | grep skfwe
docker service inspect skfwe-prod_fwe-worker --format '{{.Spec.TaskTemplate.ContainerSpec.Image}}'

# read Nextcloud as svc-fwe from inside the worker (never print the password)
c=$(docker ps -q -f name=skfwe-prod_fwe-worker | head -1); docker exec -i $c python3 - < script.py

# Windmill API, workspace fwe (token supplied by the coordinator, never printed)
curl -s -H "Authorization: Bearer $(cat <token-file>)" https://skflow.nativeassetmanagement.com/api/w/fwe/jobs/list

# skmail on chiap08
~/.skenv/bin/skmail tail 20
~/.skenv/bin/skmail send <from> <to> <urgent|normal|fyi> <re> "msg"

# open a PR on skgit (fj CLI cannot create PRs; use the API, token from the coordinator)
POST /api/v1/repos/smilinTux/hammerTime/pulls   {title, head, base:"main", body}
```

## 5. Process ids and stage types

`inquiry-candidate`, `one-stepper-acceptance`, `two-stepper-acceptance`,
`two-stepper-dishonor`, `two-stepper-certificate`, `dishonor`,
`clerk-rejection-acceptance`, plus legacy `inquiry` and `acceptance`. The registry is
growing to one entry per letter type with HOLD entries for the 17 held branches
(in progress, 2026-10-18).

## 6. Current examples

Matters `FWE-2026-0004` to `0008` are the live worked examples (0004 inquiry, 0005
one-stepper, 0006 two-stepper, 0008 clerk-rejection; 0007 is a single-step matter). `0001` to `0003` are legacy
synthetic matters. Study and practice material moves to `Matters/Library/` (in progress,
2026-10-18). Real and sample matters come later through `Matters/Intake/FWE/`.

## 7. In progress on 2026-10-18

## 8. When stuck

Ask in skmail or to the coordinator. Do not work around a refusal by writing to Nextcloud
directly, and do not guess a form. A HOLD is a correct result.
